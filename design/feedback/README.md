# Tester screenshots

Committed, and that is deliberate — the same rule `.gitignore` states for everything
else in `design/`.

An image lives in git here **iff** it is a reference or irreproducible evidence.
`design/screenshots/` is regenerated by `pnpm shots`, so it is ignored.
`design/renders/` is the reference the app is measured against, so it is committed.
`design/device/` holds frames off a real phone that no tool can reproduce, so it is
committed — including a broken one kept on purpose.

These are the same case as `design/device/`, with one extra reason: eas-cli's own type
says so.

> `TestFlightScreenshot` — *"Its URL expires after a short while."*

An issue whose only evidence is a signed Apple URL decays into a description of a
picture nobody can see. So `tools/feedback-to-issues.mjs` downloads the bytes and
commits them here before filing, and the issue links to the committed copy.

Filenames are `<app-store-connect-feedback-id>-<n>.png`. The id is the same one in the
issue's hidden `<!-- testflight:screenshot:… -->` marker, so an image and its issue can
always be matched back up.

**Nothing regenerates this directory.** If you delete a file here, the issue that
references it loses its evidence permanently — Apple's copy will already have expired.

Commits landing here are excluded from CI by `paths-ignore` in
`.github/workflows/checks.yml`: a tester screenshot changes no source, and re-running
the full Docker suite for one would cost five minutes to prove nothing.
